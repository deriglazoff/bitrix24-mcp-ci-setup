# Спецификация: файл запуска проекта .exe

## Задача

Чтобы поднять Bitrix24 MCP на Windows, сейчас нужно открыть терминал, найти папку проекта и набрать команду. Нужен обычный файл, по которому щёлкнул — и шлюз запустился.

## Решение

В корне проекта появляется `Bitrix24-MCP.exe`. Двойной клик открывает консоль, поднимает HTTP-шлюз этого репозитория и оставляет окно открытым, пока сервер работает. Закрыл окно — сервер остановился.

## Решения по реализации

1. **Тонкая запускалка, не упакованное приложение.** `.exe` не тащит Node и не бандлится через pkg/nexe. Почему: в проекте уже Node 18+; бандл — десятки мегабайт и новые зависимости, которые пользователь не просил.
2. **Компиляция C# через встроенный `csc.exe` (.NET Framework) или `dotnet`.** Почему: на Windows это есть без `npm install` новых пакетов (ставить пакеты без просьбы нельзя).
3. **Исходник + собранный `.exe` в репо.** Почему: «файл запуска» должен работать сразу; исходник нужен, чтобы не держать непрозрачный бинарник.
4. **Старт: `node server-http.js`, не `npm run start:http`.** Почему: прямой Node не зависит от того, найден ли `npm.cmd`; поведение то же, что у скрипта `start:http`.
5. **Подхват `.env` самой запускалкой.** Почему: у Node-сервера нет dotenv; Linux-деплой делает `source` env-файла. Без этого двойной клик не увидит `B24_DEFAULT_WEBHOOK`.
6. **Консоль остаётся.** Почему: иначе ошибка мелькнёт и пропадёт; логи шлюза — единственная обратная связь.
7. **`npm install` только если нет каталога `node_modules`.** Почему: каждый запуск с install — минуты ожидания; отсутствие каталога = первый запуск.

## Границы и швы

Один модуль: запускалка. Публичных границ между несколькими сборками нет — всё делает один таск.

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `launcher` | поиск корня (каталог `.exe`), чтение `.env`, проверка Node, при необходимости `npm install`, запуск `node server-http.js`, пауза при ошибке | вход: двойной клик / запуск `Bitrix24-MCP.exe`; выход: процесс HTTP-шлюза на консоли или сообщение об ошибке на русском и код ≠ 0 | разбор `.env`, поиск `node`/`npm` в PATH, тексты ошибок, ожидание клавиши |

Шов для тестов — поведение запускалки как процесса:

- нет Node в PATH → ненулевой код, в выводе есть «Node.js»
- нет `server-http.js` рядом → ненулевой код, в выводе есть указание на корень проекта
- `.env` с `PORT=…` → дочерний Node получает эту переменную (проверка разбора без поднятия шлюза, если вынесен чистый разбор; иначе — смоук через переменную окружения запускалки)

Идеал — один шов: запуск `.exe` / собранного бинарника как процесса и проверка stdout/stderr + exit code. Не поднимать реальный Bitrix24 в этих проверках.

## Вне рамок

| Требование | Почему не сейчас |
|---|---|
| stdio-вход `npm start` / `index.js` | из `.exe` бесполезен: его поднимает MCP-клиент, не человек |
| упаковать Node внутрь `.exe` | пользователь не просил автономный дистрибутив; нужен установленный Node 18+ |
| Linux / macOS-запускалка | бриф — `.exe` |
| служба Windows, автозагрузка, установщик, ярлык на рабочий стол | бриф — файл запуска по проекту |
| GUI, трей, иконка бренда | консоли достаточно |
| смена порта/вебхука из UI | уже есть `.env` |
