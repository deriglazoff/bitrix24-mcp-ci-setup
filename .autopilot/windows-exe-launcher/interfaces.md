# Интерфейсы

## Границы, решённые в спецификации

Один модуль: запускалка. Публичных границ между несколькими сборками нет — всё делает один таск.

| Модуль | Владеет | Выставляет | Прячет |
|---|---|---|---|
| `launcher` | поиск корня (каталог `.exe`), чтение `.env`, проверка Node, при необходимости `npm install`, запуск `node server-http.js`, пауза при ошибке | вход: двойной клик / запуск `Bitrix24-MCP.exe`; выход: процесс HTTP-шлюза на консоли или сообщение об ошибке на русском и код ≠ 0 | разбор `.env`, поиск `node`/`npm` в PATH, тексты ошибок, ожидание клавиши |

Шов для тестов — поведение запускалки как процесса:

- нет Node в PATH → ненулевой код, в выводе есть «Node.js»
- нет `server-http.js` рядом → ненулевой код, в выводе есть указание на корень проекта
- `.env` с `PORT=…` → дочерний Node получает эту переменную (проверка разбора без поднятия шлюза, если вынесен чистый разбор; иначе — смоук через переменную окружения запускалки)

Идеал — один шов: запуск `.exe` / собранного бинарника как процесса и проверка stdout/stderr + exit code. Не поднимать реальный Bitrix24 в этих проверках.

## Правила проекта

- Стек: Node.js ≥ 18, ESM (`"type": "module"`), уже есть `npm start` (stdio) и `npm run start:http` (`node server-http.js`).
- HTTP-шлюз: `server-http.js`, порт `process.env.PORT || 5015`.
- Тесты проекта: `npm test` (`node test/readonly.test.mjs`). Смоук шлюза: `test/http-smoke.mjs`. Новые проверки запускалки — рядом, не ломая существующие.
- Не ставить новые npm-пакеты. Компиляция `.exe` — встроенный `csc.exe` (.NET Framework) или `dotnet`.
- Не трогать логику MCP-инструментов в `src/`, деплой в `deploy/`, CI, Dockerfile.
- Секреты не писать в код и не коммитить `.env`. `.env.example` уже есть.
- Нет зависимости → вернуть `BLOCKED`, а не `npm install` чужого пакета.

## Из сборки — запускалка

- `Bitrix24-MCP.exe` в корне — Windows PE, консоль, рабочая папка = каталог `.exe`.
- Старт: `node server-http.js`. Если нет `node_modules` — `npm install`, затем старт.
- `.env` в корне читает сама запускалка; уже заданные переменные среды не перезаписываются.
- Ошибка (нет Node, нет `server-http.js`, ненулевой код) — текст на русском в stderr; пауза только если stdin не перенаправлен.
- Пересборка: `powershell -ExecutionPolicy Bypass -File scripts/build-launcher.ps1` (`csc.exe`).
- Тесты шва: `node test/launcher.test.mjs` (на не-Windows сразу 0).
