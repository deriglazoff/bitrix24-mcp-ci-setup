2. Цель проекта

Разработать систему на базе ИИ для прогнозирования вероятности и срока погашения задолженности клиентом. Основная задача — повысить эффективность процесса взыскания за счет:
- Тактическая помощь специалистам: Предоставление специалистам по взысканию информации для выбора наилучшей тактики работы с клиентом.
- Стратегическое планирование: Предоставление руководству данных для анализа, формирования выборок и выстраивания стратегии работы с различными сегментами клиентов.
- Фокусировка усилий: Концентрация ресурсов на наиболее перспективных для взыскания клиентах.

3. Требования и ожидания

3.1. Отображение результатов
- Ключевой показатель (вероятность погашения) должен быть виден непосредственно в карточке клиента в основном рабочем ПО.
- Данные также должны быть доступны в реестрах для возможности формирования аналитических выборок.

3.2. Желаемый функционал (Ансамбль моделей)
Проект предполагается развивать итерационно, добавляя новые прогнозные модели.
- MVP: Прогноз вероятности погашения задолженности.
- Дальнейшее развитие:
    - Определение наилучшего канала коммуникации с клиентом (входящие/исходящие звонки, чаты).
    - Прогноз типа погашения: возврат в график, полное погашение, частичное досрочное погашение.
    - Типизация клиентов для выбора стратегии (например, чтобы понимать, стоит ли на поздней стадии настаивать на полном погашении или лучше предложить возврат в график, чтобы не потерять клиента).

3.3. Автоматизация
В долгосрочной перспективе, при достижении высокой точности прогнозов, данные могут быть использованы для автоматизации процессов, например, для автоматического перевода клиентов между статусами или реестрами.

4. Источники данных

Для обучения модели планируется использовать все доступные данные о клиенте:
- Внутренние данные:
    - Полная информация из карточки клиента в ПО.
    - История взаимодействий: контактность, исполнение/неисполнение обещаний.
    - Данные первоначального скоринга от системы "Авиа" (количество и типы исполнительных производств, история банкротства).
    - Существующий отчет в Power BI "Скоринг постоянного клиента на красном статусе" (автор — Александр Николашин).
- Внешние данные:
    - Сигналы из НБКИ (Национальное бюро кредитных историй).
- Существующая аналитика:
    - Система "Авиа" уже рассчитывает потенциальную дефолтность клиентов. Ключевой момент: этот отчет сейчас формируется вручную в Excel. В рамках проекта предложено рассмотреть создание сервиса для автоматизации этого расчета.

5. План реализации MVP

- Подход: Итерационный. Начать с одного ключевого, наиболее важного показателя.
- Первый показатель (MVP): Прогноз, на какой неделе в течение первых 120 дней просрочки клиент с наибольшей вероятностью совершит платеж.
    - Период 120 дней выбран как критически важный (до возможной продажи долга по цессии).
    - Разбивка по неделям предложена как сбалансированный вариант между точностью и детализацией прогноза.
- Технический план:

    3.  Построение и обучение модели.
    4.  Валидация модели на ретроспективных данных для оценки точности.

- Инфраструктура: Зависимость от стабильности основной системы ("поло").
- Оценка этих рисков — одна из первых задач на этапе исследования.
